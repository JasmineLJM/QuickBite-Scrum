# QuickBite Scrum Practice

Personal simulation for learning the assignment workflow. This is not evidence of participation by four actual students.

## Working approach

Complete one assignment part, then document what was actually done. Keep unfinished work marked as pending. Real team execution and evidence are required for the assessed submission.

## Structure

- src/: application code (technology to be chosen)
- tests/: tests
- docs/report/: one Markdown file per completed assignment part
- docs/scrum/: planning and meeting records
- docs/evidence/: screenshots and other evidence

## Progress

- [ ] Part A: team responsibilities
- [ ] Part B: Product Backlog and Definition of Done
- [ ] Part C: Sprint Planning
- [ ] Part D: Sprint execution and working Increment
- [ ] Part E: at least three Daily Scrums
- [ ] Part F: requirement change and adaptation
- [ ] Part G: Sprint Review and feedback
- [ ] Part H: Sprint Retrospective
- [ ] Agile Reflection

## Git workflow

Use a branch for a small unit of work, make meaningful commits, and review changes before merging. When GitHub is connected, use pull requests to record review. A personal rehearsal does not demonstrate independent teammate review.
